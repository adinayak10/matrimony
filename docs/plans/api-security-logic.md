# Track A — API security + business-logic remediation (api.banjaramatch.com, Express 4 + mongoose 8 + socket.io 4)

Facts this plan relies on (verified on the box): DB `aasd` has 320 users, 1 admin, 3 `is_block=1`, 28 `gender:'Not specified'`, 0 users with the legacy `blocked` array, 2 `Block` rows (one pair written twice), 11 chat rooms (0 duplicate pairs), 7 `Setting` documents (6 empty, from seed.js), ChatRoom's unique multikey index was never built (only `_id_`), no TTL indexes anywhere, `login_type` is only 2 (email) or 3 (google) so no OTP-created accounts exist, 41 mobile users / 9 active in 30 days, pm2 env has no JWT_SECRET (dotenv only), `file-type@19.6.0` is ESM-only. ## risks
- API authenticate goes live before the web forwards the cookie token on its server-side dashboard calls (routes/index.js:754-848, 931: fetchUsersList, getInterestList x3, getProfileVisitorSummary x3, getShortListedUsers, getTopDailyMatches) → dashboard/shortlisted pages render empty. Mitigation: web change ships first (A0 wave 2 order), API accepts cookie or Bearer; verify dashboard before enabling.
- httpOnly cookie removes document.cookie access that the web client JS uses for Bearer (all-profiles.ejs:411 etc.) → browser calls 401. Mitigation: web switches to credentials:'include' (CORS already credentials:true, cookie domain .banjaramatch.com) in the same deploy window; API keeps accepting both cookie and Bearer.
- JWT_SECRET rotation logs out every web and app session at once. Mitigation: announce, do it in wave 3 at low traffic, verify app login flow (firebase-google-login) immediately; app bounces to LoginScreen (splash_controller.dart:33-37), no crash.
- Admin role-check moved behind bcrypt and aud:'admin' claim: an existing admin cookie/token stops working → admin must log in again. Mitigation: do with the rotation (everyone re-logs in anyway); admin panel uses the body token from localStorage so no cookie dependency.
- Making firebaseToken mandatory could reject an older app build that omits it. Evidence: both reachable app flows always send firebaseToken (user_service.dart:821-871), web too (login.ejs:327/536, register.ejs:285); if getIdToken returns null the app sends '' → 400. Mitigation: log 400s on these routes for a week before deleting the fallback-free path is irreversible; keep the error message explicit ('Please update the app').
- Socket handshake auth made mandatory too early breaks chat/badges for every installed app (socketservice.dart sends no auth). Mitigation: dual mode gated by settings.security.legacySocketJoin (default true); flip only after the auth-aware build is mandatory and legacy_socket_join log lines hit zero.
- Returning empty lists for 'Not specified' viewers (28 users) changes their experience. Mitigation: message in the response + existing onboarding redirect; report script gives the owner the list for outreach.
- Gotra exogamy exclusion may hide legitimate matches if gotra data is wrong (38 users have no gotra → not excluded) and motherGotra is new (empty for all). Mitigation: admin toggle matching.enforceGotraExogamy; applies only when the viewer's gotra is set.
- New unique indexes (ChatRoom.pairKey, FriendShipRequest.pairKey, RecentVisitor visitor+visited, UserReport reportedBy+reportedUser) fail to build if duplicates exist → mongoose logs an error and queries still run but without protection. Mitigation: run dedupe tools (A8.2/A8.7) and check `db.<coll>.getIndexes()` after boot; keep the old multikey index definition removed so it stops erroring.
- express-mongo-sanitize strips any body key starting with '$' or containing '.'; the app sends settings as a JSON string and filters with plain keys so nothing legit is affected, but verify editProfile multipart (settings/horoscope/family JSON strings) still parses.
- helmet default Cross-Origin-Resource-Policy: same-origin would block www from loading api /uploads images. Mitigation: crossOriginResourcePolicy:{policy:'cross-origin'} and the explicit header on /uploads.
- Binding to 127.0.0.1 while nginx proxies to 'localhost' (resolves to ::1 and 127.0.0.1) can add failed IPv6 connects. Mitigation: change proxy_pass to 127.0.0.1:4002 in the same change, nginx -t, reload.
- Rate limits without app.set('trust proxy',1) would key every request on nginx's IP and throttle everyone. Mitigation: set trust proxy before limiters; test with two IPs/curl loops.
- sharp is a native module; npm ci on the server must succeed (prebuilt binaries for linux-x64 glibc, Node 18/22 OK). Mitigation: if install fails, ship the file-type sniff + extension normalisation first and add sharp later.
- Photo default 'pending' plus any client that filters on moderationStatus==='approved' would hide new photos. Evidence: only getUserPhotos filters ($ne:'rejected') so pending stays visible; admin photo-moderation.html lists by status (unchanged).
- deleteRoom becomes per-user hide instead of hard delete; the app expects status:true and roomId — keep that response shape.
- Deleting legacy auth routes: any unknown client still calling verify-otp gets 404/410. Evidence: no login_type:1 users exist; the shipped app cannot reach the OTP screen (login_screen.dart:58-64 commented out).
- The 150mb body limit drop to 1mb could reject a legit multipart? No — multer parses multipart itself with its own 5MB/100MB limits; only JSON/urlencoded bodies are capped. nginx client_max_body_size must be raised on the upload locations.
