## decisions
- extractToken order is Bearer first, then the legacy `token`/`bm_session` cookie (integrator conflicts #1 and #3 make the cookie a 14-day fallback only and say a stale cookie must never override the Bearer), i.e. the reverse of the old cookie-first authMiddleware.
- verifyUserToken loads the user with .lean() and selects `_id role is_block tokenVersion gender gotra family settings email full_name` (the task's list; `family` covers family.motherGotra once the field exists); req.user is a plain object, req.userId a string, req.isAdmin a boolean.
- resolveCaller(req, fields) defaults to ['my_user_id','userA_id'] so caller=my_user_id/target=user_id routes (blockUser etc.) do not log a mismatch on every call; self-scoped routes pass ['user_id']. requireSelfOr403(req, bodyField) returns {ok} / {ok:false,status:403,body} (controllers already have try/catch and res in scope) and selfOnly(field) is the middleware form for userRoutes.
- ACCOUNT_BLOCKED and TOKEN_REVOKED are 401 (not 403) so the web ensureAuth and the Flutter splash both bounce to login, as A1.1 requires; a missing `tv` claim counts as 0 so pre-rotation tokens stay valid until logout.
- profileSerializer returns a reduced `settings` object for other viewers (only the visibility flags clients need to render request-photo / connect buttons), strips notification preferences, profileCompletion and tokenVersion; admin viewers are treated like self.
- buildMatchQuery applies exactly the two exogamy clauses in A6.1 (candidate.gotra not in {own, mother's}; candidate.family.motherGotra != own); it does not exclude candidates whose mother shares the viewer's mother's gotra (owner decision, recorded in integrator owner_actions). Gotra inputs may be populated docs or ids (toId normalises).
- theirPreferenceFilters treats a missing preferences.* path as 'accepts anyone' ($exists:false / $size:0) so users created before the preference defaults are not silently excluded; age/height range clauses are skipped when the viewer has no dob/height.
- blocks.blockUser is an idempotent upsert (returns created:false on repeat instead of 400) and deletes only PENDING FriendShipRequests plus Shortlist rows both ways; unblockUser touches only the blocker's own row.
- firebaseAuth: if the email-matched user already has a different non-empty firebase_uid the service warns and returns the user without relinking (Firebase enforces one account per email, so the token holder controls that email); 'google' provider check is strict, other providers are not checked unless passed.
- userCascade also removes CallLog rows and uses the real RoomUser.user_id / Room.admin_id / SavedNotification.my_user_id|user_id fields (deleteUsers.js used wrong names for those too); supports dryRun counts for purge-fake-users.
- rateLimits: limiters are skipped under NODE_ENV=test unless RATE_LIMIT_TEST=1 (the auth-required suite alone would exceed authLimiter); both `limit` (v7) and `max` (v6) are passed; IPv6-safe ipKeyGenerator is used when the installed version exports it; a blogLikeLimiter (10/h) is included for A7.3's /api/blogs/:slug/like.
- validateImages re-encodes to <uuid>.jpg via sharp (integrator #13 replaced file-type); with sharp unavailable it falls back to extension+mime allowlist and a random rename, logging once; a single bad file rejects the whole request and unlinks every received file.
- tools/_guard.js requires --yes-i-know (and --prod for db 'aasd') only for runs that write (--apply, or guard({writes:true})); dry runs need only MONGODB_URI, matching A10's `node tools/cleanup/purge-logs.js` (no flags) verification. MONGODB_URI is never defaulted.
- Cleanup scripts use `{strict:false}` / `setOptions({strictQuery:false})` where they touch fields not yet in the schemas (ChatRoom.pairKey, User.is_fake) so they run before the model changes land; dedupe-settings prefers the prod doc id 69287b6712fb5b6b9b3fb6e4 and accepts --keep=<id>.
- Tests: each suite is wrapped in defineSuite() and exported; harness.suiteReady() registers a single skipped test when app.js or the dev dependencies are missing, so `node --test` is green today; all heavy requires (supertest, mongodb-memory-server, models) are lazy because Node's default pattern also executes test/helpers/*.js. Assertions on list shapes use a deep ObjectId walk so they hold regardless of each endpoint's data wrapper.
- publicLookupRoutes.js exposes router.PUBLIC_PATHS for the auth-required suite; fetchSetting/download-apk stay in settingsRoute.js as the spec says.

- check-ejs-raw written as apps/web/scripts/check-ejs-raw-web.js (under apps/web, not repo-root scripts/) to avoid the admin agent's file; it scans views/**/*.ejs (both <%- sinks and inline-script innerHTML literals) and non-vendor public/js/*.js; allowed prefixes include(, jsonLd(, safeJson(, asset(, img(; EJS_ALLOWED_SITES left empty until Track A sanitises CMS HTML
- apiProxy.js loads http-proxy-middleware in a try/catch: when the dep is missing the module still loads and /api/* answers 503 JSON instead of crashing app.js; proxy strips Cookie, injects Bearer from bm_session||token (legacy window), deletes upstream Set-Cookie, runs fixRequestBody; Express 5 path matching via req.path.startsWith('/api') wrapper
- routes/auth.js CSRF: requires Content-Type: application/json by header (not req.is, which passes empty-body form posts) and rejects a foreign Origin; cookie `secure` is true in production or when req.secure (so local dev over http works); API calls use an 8 s timeout (Firebase token verification is slower than the 3 s SSR default); isNewUser = /registration/i on the API message (AuthController sends 'Registration successful'); redirect = /thank-you for new users, else validated returnTo cookie or /dashboard; legacy token cookie cleared on login so it cannot shadow bm_session

- errorHandler answers JSON for /api, /auth, /csp-report, XHR and Accept: application/json; 4xx body-parser errors keep their status with a generic message; renders fall back to text/plain if the error page itself fails
- 503/500 pages are standalone (no head.ejs, only /css/bootstrap.css + /css/style.min.css) but include header/footer with user:null, since those partials need no API data; 503 'Try again' links back to res.locals.currentPath
