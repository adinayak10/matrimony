# banjaramatch: audit, monorepo, auto-deploy, admin base UI, SEO/perf

## Context

banjaramatch.com is a Banjara-community matrimony platform running on this VPS as three separate directories and PM2 processes (web on 4000, API on 4002, admin on 4001), plus a Flutter app folder nested inside the web directory. Only the API is a git repo (adinayak10/matrimony-api, main, with 19 modified + 152 untracked files and secrets + user photos tracked). The owner wants:

1. Business-logic loopholes and filter bugs found (and fixed).
2. Admin panel rebuilt on one shared base layout.
3. Website UI fixes, speed and SEO work to push "banjara matrimony" from top-10 toward top-3.
4. One production-ready monorepo folder `banjaramatch/` holding web, api, admin, flutter app, deploy tooling.
5. Push to `main` auto-deploys and restarts everything, so work can happen from any laptop.
6. Zero change to public URL slugs already indexed.

A 16-agent read-only audit (365 findings) and a 5-agent design pass produced this plan. The full per-track designs (API security/logic, monorepo/deploy, admin UI, website SEO/perf) and the integrator's conflict resolutions live in `/tmp/claude-0/-var-www/e5f933f1-090f-47d4-9e03-42ffdb9e8f07/scratchpad/designs/*.md` (≈250 KB, with file:line citations for every step) and the audit reports in `../reports/*.md`. **Phase 1 step 1 copies them into `docs/plans/` in the repo** so they survive this session. This file is the executable summary.

## Decisions taken (stated assumptions; say so if any is wrong)

- **Hosts stay exactly as they are**: `www.banjaramatch.com`, `api.banjaramatch.com`, `admin.banjaramatch.com`. The Flutter app hardcodes `https://api.banjaramatch.com/` in `lib/utilities/const.dart`, so moving the API host would break every installed app. "All comes in banjaramatch" means one repo/folder, not one hostname. The web gets a same-origin `/api/*` path alias as a by-product (Phase 3d), and admin./api. subdomains remain.
- **Fresh git history for the monorepo.** `matrimony-api` tracks `serviceAccountKey.json`, `cert/AuthKey_*.p8`, `config.json` (DB creds), 215 user profile photos and an APK. Its history is treated as leaked (rotate the keys, archive the repo). The monorepo is built from the **working trees** (the production code is 19 modified + 152 untracked files ahead of HEAD).
- **Admin panel stays vanilla HTML/CSS/JS, rendered through EJS layouts** by its own Express server (ejs is already a dependency; `views/pages`, `views/partials` exist but are empty). No SPA framework.
- **Deploy style = in-place checkout + GitHub webhook + health-check + rollback-to-previous-sha**, modelled on the hook that is actually live for feribazaar (`/root/feribazaar-autodeploy/listener.js` + `deploy.sh`), not the releases/current layout in feribazaar's `deploy/README.md` (needs a `deploy` user, Redis, worker role; overkill for three single-instance apps).
- **Node 22.23.2 for all apps** (`.nvmrc`, absolute interpreter path in pm2; the apps run Node 18 today). Every loopback URL becomes literal `127.0.0.1` (Node 17+ resolves `localhost` to `::1` first).
- **pm2 cluster mode, 1 instance, `wait_ready`** so `pm2 startOrReload` is a real overlapped reload. The one-time cutover uses bridge processes on 4100-4102 + nginx reloads (zero 502s) because `startOrReload` cannot change exec_mode.
- **ufw stays off.** Binding the three apps + hook to `127.0.0.1` closes ports 4000-4003 without touching the ~15 other tenants' ports. Enabling ufw is an owner decision after confirming the SSH port.
- **Product is free** ("Completely Free Forever", no payment integration, plans admin-assigned only). No paid gating is built; `onlyPremium` settings collapse to `everyone`; premium score bonuses and `RemainingProfileImageView` reads are removed; `assignMembership` stays admin-only.
- **Fabricated trust content is removed, never replaced**: "Trusted by 1,500+ couples", "10,000+ verified profiles", `AggregateRating 4.8/2847`, placeholder phone `+91-9876-543-210`, stock "Happy Couples", "Aadhaar verification" claims, regional "150+/500+" fallbacks, `/user/fake-batch`.
- **Session design (integrator resolution)**: the API never sets cookies any more. Web sets its own host-only httpOnly `bm_session` via `apps/web/routes/auth.js` (proxies login to the API with `device_type:'web-proxy'`) and browser JS calls a same-origin `/api/*` proxy that injects the Bearer. Admin sets host-only httpOnly `admin_session` via its own server and proxies `/api/*` with the Cookie header stripped. The installed app keeps sending `Authorization: Bearer`. The legacy `.banjaramatch.com` `token` cookie is honoured for 14 days then dropped.
- **JWT_SECRET** (currently the public default) is rotated the same day as the cutover, right after the rollback drill passes; one shared value in `api.env` + `web.env` (web still verifies locally until Phase 3a), never in `admin.env`. Everyone re-logs in once; the app lands on LoginScreen, not a crash.
- **Socket auth is dual-mode** (`settings.security.legacySocketJoin`, default true) until the owner ships an app build that sends `auth.token` and marks it mandatory; flip only when `legacy_socket_join` log lines are zero for a week.
- **16 city regional pages go `noindex, follow`** (still 200, still linked, out of the sitemap) until each has ≥300 unique CMS words; the 8 state pages stay indexed. Needs owner sign-off (Phase 5).

### P1 — business-logic loopholes and filter bugs

- **Blocks are ignored** in the main list, daily matches, nearby and trending (wrong block store: `Block` collection vs `User.blocked` array); the blocked person can lift a block placed on them; `fetchProfile` ignores blocks and notifies the blocker of the blocked user's visit. `UserController.js:1640,1891,981`
- **Opposite-gender rule** fails for the 28 users with gender `Not specified` and is missing from nearby matches. `:1897`
- **"Match my preference" returns zero results** whenever caste/gotra/qualification/profession preferences are set (populated objects compared to ObjectIds); **"match their preference" is a no-op**; **income filter compares a field that does not exist**. `:1940-1991`
- **No same-gotra exclusion** anywhere server-side (gotra exogamy is the core Banjara rule). `:4004`
- **Membership gating and expiry are not implemented**; photo-view counters and privacy settings (hide photos/income/location) are saved but never enforced. `:1207,3006`, `web/views/pages/user-setting.ejs:168`
- **Interests**: no self/duplicate/blocked-target/rate checks; shortlist toggle sends unlimited emails. `:2411`, `services/emailService.js:103`
- **Admin "Block" does nothing**: `is_block=1` users still log in and pass `authenticate`/`adminAuth`. `AuthController.js:838`
- **Matching responses return full user documents** incl. password hash, device tokens, coordinates, phone/email; admin user-detail displays the hash. `:3972`, `models/User.js:77`
- **Reports** can be spoofed/flooded; app-side `reportStatus` reports never reach the admin queue. `:5218`
- **Chat**: anyone can message anyone (pending room auto-created); contact-info filter drops normal messages containing `wa`, `ig`, `fb`; presence broadcast to everyone incl. blocked users; `join` runs O(N) populates per online user; `$roomId` vs `$room` aggregation bug. `socket.js:75,101,379,591`
- **Unbounded collections** for 320 users: searchlogs 9333, activitylogs 3051, notifications 2609, recentvisitors 1074 — no TTL. ChatRoom's unique multikey index can never build (duplicate 1:1 rooms possible). `models/ChatRoom.js:14-20`
- **Registration dead-ends**: Firebase account created before the backend call; duplicate phone leaves the user stuck. Gender lock / 18+ enforced only in HTML. `web/views/pages/register.ejs:274`, `onboarding.ejs:529`
- **Blog edit regenerates the slug from the title**, changing live URLs. `controllers/admin/blogController.js:273`
- **Draft regional pages are served** by slug (city and state). `cityRegionalPageController.js:426`, `stateRegionalPageController.js:395`

### P1 — admin panel (why "so many UI issues")

- 22 standalone HTML pages, no shared layout: three different navs (15-link sidebar, 7-link sidebar, Bootstrap navbar with 4 links), `community-feedback.html` has its own nav/CSS, `contact-enquiries.html` is two HTML documents concatenated, `views/` empty, 334/254/240-line inline `<style>` blocks, page-local `API_URL` constants, `window.fetch` monkey-patches, seven page-local `logout()` overrides (several redirect to `/login` which 404s).

Admin user detail/activity/delete query wrong schema fields. Admin login has no rate limit and checks role before password (enumeration).

- ✔ Good base: all 56 sitemap URLs 200, self-canonical, unique titles; home title+H1 lead with "Banjara Matrimony"; one-hop redirects; real 404; no cloaking; TTFB 50 ms.
- ✔ **State pages link to no city pages** (template reads `page.interlinking.relatedCityPages`, API sends `relatedCityPages`); city pages have no breadcrumb/parent link; the 16 city pages are reachable only from `/sitemap`. Regional pages are 82-84 % identical text with always-0 real stats (query uses non-existent `isActive`/`isVerified`) masked by hardcoded "150+/500+" fallbacks → doorway-page risk.

Category listings: broken relative images, links through 301s. `/account-deletion` lacks canonical/description. Broken internal links (`/testimonials`, `/interests`, `/matches`, `-mumbai`, `/safety-tips`). `favicon.ico`, `apple-touch-icon`, `site.webmanifest`, `/.well-known/assetlinks.json` all 404 (App Links `autoVerify` fails).

- **Analytics/legal**: `/thank-you` fires Google Ads conversions on every visit (2-3× double counting); privacy policy omits GPS + Ads/GA tracking, no cookie consent; terms mention subscription fees for a free product.

## Implementation phases (ordered; production never breaks)

Each phase ends with its verification block. Every push after Phase 1 deploys automatically, so breaking changes land only after the rollback drill is proven.

### Phase 0 — Baseline + hot patches on the OLD tree (day 0, no code deploy)
1. Owner rotates `admin@banjaramatch.com` password (default is in publicly served files). Delete `admin/public/{debug,test-auth,flow-test,test-dashboard}.html` (nginx then 404s).
2. Hot patch nginx: `location = /webhook { return 410; }` in `sites-available/api.banjaramatch.com`; `nginx -t && systemctl reload nginx`.
3. First-ever `mongodump --db aasd --gzip`; tarballs of the three working trees (local only); `git -C api diff > api-uncommitted.patch`.
4. Write `deploy/check-urls.sh` + `deploy/url-contract.txt` (sitemap URLs + legacy map + router 301s + files + api/admin probes) and capture `urls-before.jsonl`; `deploy/psi.sh` PSI baseline (needs the owner's PSI API key); record `pm2 jlist`, `ss -ltnp`, `free -m`; `autocannon` baseline via `deploy/loadtest.sh`.

### Phase 1 — Monorepo skeleton + deploy pipeline + zero-502 cutover (~1 day; production untouched until M1)

Create `/var/www/banjaramatch-shared/*` dirs; copy (never move) runtime files per the table; write the four env files (web: `HOST`, `AUTH_SERVER_URL=http://127.0.0.1:4002`, `API_URL`, **current** `JWT_SECRET`; api: `PORT/HOST/MONGODB_URI/FIREBASE_SERVICE_ACCOUNT_PATH/BLOG_IMAGE_DIR/FRONTEND_URL`; admin: `API_INTERNAL_URL/API_PUBLIC_URL/SESSION_TTL_HOURS=8`, no secret; deploy: `WEBHOOK_SECRET/WEBHOOK_PORT=4003/BACKUP_RETENTION_DAYS`).

## Risks worth re-reading before each phase

- `git reset --hard` + any tracked runtime path = data loss → `.gitignore` first, `git ls-files` gate, `link_shared` never recurses into a symlink, no `git clean`.
- Node 18 → 22: `localhost` is `::1` first → literal `127.0.0.1` everywhere; the bridge start is the Node 22 test before traffic.
- API `authenticate` before the web forwards the cookie token (3a before 3b) or the dashboard renders empty.
- httpOnly cookies before the same-origin proxy + 13 template edits (one deploy) or every logged-in page 401s.
- Socket auth enforced before the mandatory app build → chat dead for every installed app; dual mode + settings flag.
- CSP enforced too early breaks the Firebase popup/GA/Agora → Report-Only first, host list from the views grep.
- PurgeCSS strips runtime plugin classes → safelist + visual QA; old `/css` paths stay for rollback.
- New unique indexes fail on duplicates → run the dedupe tools first, check `getIndexes()` after boot.
- `npm ci`/build on a box with ~400 MB free RAM → only when the lockfile changed, `--max-old-space-size=768`, abort below 600 MB available (keep the running release).
- EJS view cache: template edits are invisible until pm2 reloads; never hot-edit views on the box.
