# BanjaraMatch: full matrimony feature expansion (API + admin + website + mobile)

## Context

banjaramatch.com runs from the monorepo `/var/www/banjaramatch` (web :4000, api :4002, admin :4001, pm2 fork mode, Node 22; shared runtime tree `/var/www/banjaramatch-shared`; deploy hook on :4003 but **no GitHub remote is configured yet**). Phases 0–5 of `docs/plans/00-master-plan.md` (security, monorepo, admin shell, SEO/perf) are done and live. The owner now wants the product itself to grow: a mobile app that feels complete instead of a thin four-tab client, more admin functionality, and matching website features.

What the inventory found:

- **Mobile** (`apps/mobile`, Flutter/GetX, 259 Dart files): 4 reachable tabs (Explore, Matches, Interests, Chats) + drawer. Finished screens are unreachable (Settings, FAQ, Languages, Block list, Ice Breaker, AI About). ~40 files of leftover social-app code (feed/posts/stories/rooms/random/ads/Firestore/RevenueCat). Hardcoded numbers ("95% response rate", Explore stats, static "AI Recommendations"). Chat from cards says "Coming Soon". Notification taps go nowhere. The app calls endpoints the API does not serve (`fetchFAQs`, `fetchPlatformNotification`, `profileVerification`, `pushNotificationToSingleUser`, `uploadFile`). `getTopDailyMatches()` in the app calls the wrong URL.
- **API** (`apps/api`): good matching core (gotra exogamy, blocks, daily-match scorer, privacy serializer, Guna Milan table). Gaps: scheduler never started; `guna-milan` unauthenticated; profile completeness never persisted; no verification/success-story/saved-search/announcement/FAQ models; Ice Breaker questions hardcoded; `block_reason` dropped by schema; Agora token + socket call events exist with no client; dead fields (`lastActive`, `is_top_user`) in three handlers.
- **Admin** (`apps/admin`): clean base layout, 17 pages; nothing for verification, push, analytics beyond signups, announcements, FAQ, or matchmaking. Membership tab makes you paste a raw plan id.
- **Web** (`apps/web`): already a full member web app. Horoscope edit + Guna Milan panel, an Accepted-interests tab, and notification prefs already exist. Missing: success stories, verification, saved searches, daily-matches page, announcements, dynamic FAQ, match % chips.

## Decisions (confirmed with the owner 2026-10-21)

- All four pillars: App completeness, Trust & verification, Matching depth, Community & admin tools. Plus in-app voice/video calls on the existing Agora backend. Biodata PDF deferred (superseded by docs/plans/02-biodata-maker.md, 2026-10-22).
- Mobile code is written here **uncompiled**; the owner builds on the laptop. CI unchanged.
- Legacy social code in the app is removed. If the tooling denies `git rm`, the exact list (section M1) goes to the owner.
- Product stays free: no payments, no paid gating. `/membership` upgrade action, RevenueCat, "premium" UI go away.
- No fabricated content: success stories, FAQs, announcements ship with empty states. Ice Breaker default questions are generic config and may be seeded.
- Existing app builds must keep working: API responses only **gain** fields.
- Live steps (pm2 reload, deploy, nginx) are the owner's. Everything is built and tested in the repo first.
