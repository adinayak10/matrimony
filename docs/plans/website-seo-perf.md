## risks
- EJS view cache (NODE_ENV=production) means template edits are invisible until pm2 reloads — rely on deploy.sh's pm2 startOrReload; never hot-edit views on the box.
- CSP can break the Firebase Google popup (frame-src/connect-src), GA/Ads pixels, Agora calls and socket.io — mitigation: Content-Security-Policy-Report-Only for one week with /csp-report logging, explicit host list from the views grep, crossOriginOpenerPolicy stays off; enforce only after a manual pass of /login (Google popup), /register, /user-chat (call), /dashboard.
- 301 changes (trailing-slash/case middleware, -bangalore retarget, ?category= → path, /signup → /register) can alter indexed URLs — mitigation: deploy/check-urls.sh diff against the committed baseline on every deploy; a 404 for any contract URL blocks the deploy.
- Catch-all order: any new route starting with banjara-matrimony- (hub, near-me) or file-like paths must be registered before indexRoutes; the /:slug route stays last; the API proxy must mount after indexRoutes or it shadows /api/regenerate-sitemap and /api/proxy/cities.
- Cookie migration: switching to a host-only httpOnly bm_session breaks every page that reads document.cookie unless the same-origin /api proxy and the 13 template edits ship in the same deploy; keep the legacy token fallback read for 14 days so current sessions survive; admin keeps its own cookie name.
- Socket chat: moving the browser to a same-origin /socket.io path needs the nginx location and Track A's handshake-cookie auth in the same window; the Flutter app continues to use api.banjaramatch.com without auth during the sunset period.
- nginx static serving must be limited to asset prefixes — serving public/ at / would hand out the 32 legacy .html files and bypass the 301 map; delete those files in the monorepo move regardless.
- PurgeCSS can strip classes added by jQuery plugins at runtime (chosen, slick, bootstrap collapse/modal) — safelist listed in step 33 plus a visual QA checklist (home slider, city dropdown, mobile menu, FAQ accordion, chat window) before the hashed CSS replaces the old files; old /css paths keep working for rollback.
- Font replacement changes the look of headings (5 Google families → self-hosted Poppins) — owner visual sign-off on a staging URL before enforcing; keep one display face if required.
- Removing fabricated sections changes the home layout (slick sliders slider3/couple-sli initialise on now-absent elements — harmless no-ops) and shortens content; the keyword/FAQ sections remain so 'banjara matrimony' density stays.
- Sitemap regeneration with the API down must never empty sitemap-regional.xml (24 ranking URLs) — non-empty guard + atomic rename + stale cache.
- Noindex rule for thin city pages drops them from Google until content is written — intended (doorway-risk reduction), but the owner must know the 16 city pages will temporarily leave the index; states stay indexed; pages never 404.
- Track A dependencies (isPublished in slug queries, timestamps:false on view bumps, real stats fields, sanitised CMS HTML, socket cookie auth, upload-time sharp) — the web changes degrade gracefully without them (guards in steps 10, 22, 47) but lastmod and stats stay wrong until they land.
- sharp needs a native binary; if npm ci on the VPS fails to fetch it, build/images.js falls back to cwebp/convert (present on the box) — CI on GitHub must then skip the image step.
